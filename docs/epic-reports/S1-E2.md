## What works

- Invited adults join with an invite link, a year of birth and the current terms; nothing is kept from a refused sign-up.
- Every rule is in the database: the sign-up trigger, the account gate (`email_unconfirmed` → `staff_account` → age rules → `handle_missing` → `legal_acceptance_required` → `active`), the username checks, the log-in pause and the staff roles. The screens only explain.
- Usernames can't fake staff, the brand or another person, in any script.
- Logging in, logging out, devices and password resets work, with the emails in both languages.
- Staff use the normal login in March; S1-E2-07b only has to change `is_staff_session()`.
- Only the country code is kept from the connection; the invited test admits every country.

## Breaks found where stories meet

| Found | Stories | What happened | Fixed |
| --- | --- | --- | --- |
| The top bar scrolled sideways on phones in Romanian | S1-E2-05 × S1-E1-03 | "Conectare" and "Înscrie-te gratuit" next to the language menu were wider than 390 px | In S1-E2-05: the top bar's end slot wraps |
| A confirmed sign-up was no longer active | S1-E2-01 × S1-E2-04 | The new `handle_missing` gate step holds a confirmed account until a username is chosen | In S1-E2-04: "Continue" leads to `/setup`; the sign-up tests walk through it |
| A public sign-up without a country was refused | S1-E2-01 × S1-E2-10 | With `invite_only` off, the market rules apply and an unknown country counts as closed | In S1-E2-10: the test signs up with a signed Romanian token, as the real form does |
| An axe check measured colours mid-animation | S1-E2-02 × S1-E1-03 | The year-of-birth spec ran axe during the page's entrance fade (4.48:1 in CI) | In S1-E2-02 (#152): the spec waits for animations to finish |
| Every direct table read returned 401 on staging | S1-E1-02 × every story with a table | The hosted projects grant nothing on new public tables to `anon` and `authenticated`; `auto_expose_new_tables` was unset locally, so it defaulted to true and every local test passed | In its own pull request (S1-E1-02 fix, Ghemotoc/WebApp#154): `auto_expose_new_tables = false`, explicit grants per policy, test `003`; every later story's tables grant explicitly |
| The invite field lost the typed code and the focus after a wrong code, and Continue did nothing with an empty code | S1-E2-01 × S1-E2-10 | A wrong code changes the address, so the page checks it again and draws a new gate | In this story: the gate keeps the code from the address, focuses the field and shows the reason as the field's linked error; an empty code gets "Enter the code from your invitation" |
| A refused legal page loaded for about 7 seconds before the error | S1-E14-01 × S1-E1-01 | TanStack Query retries every failed read three times by default | In this story: refusals (401, 403) aren't retried (`src/lib/query-retry.ts`) |
| An unknown address went home without a word | S1-E1-01 | The router's catch-all redirected to `/` until S1-E1-05 | In this story: a small "We can't find that page" from board 7.4; S1-E1-05 adds search and the doodles |
| Database tests saw audit rows left by browser tests | S1-E2-04, S1-E2-07a × S1-E1-02 | The audit log is append-only, so rows written by end-to-end runs stay in the local database | The tests compare only the rows they write (`created_at = now()` or their own action) |

No break needed a GitHub issue.
