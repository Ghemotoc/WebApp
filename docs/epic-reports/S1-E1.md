## What works

- One command set from a fresh clone: `npm ci`, `npx supabase start`, `npm run dev`; CI runs every check on every pull request.
- The interface opens in Romanian for everyone and switches to English from either drop-down; signed-in people keep their language on every device.
- Light and night mode follow the device, with a footer drop-down; every colour pair meets WCAG 2.2 AA, tested in CI.
- The database refuses everything by default: signed-out visitors see only public switches, and each person sees only their own profile. The audit log can't be changed by anyone.
- The account gate already answers the March rules: only invited adults can write; the minor personas are read-only, ready for the minors' launch gate.

## Known gaps

- **Branch ruleset not enforced.** Robert created the ruleset on `main` (a pull request and the three CI checks). GitHub doesn't enforce rulesets on a private repository on the Free plan, and Robert chose to leave it that way for now (`docs/decisions.md`). CLAUDE.md's no-push-to-main rule and green CI before each merge cover it.
- **`.env.example` not checked.** The repository's `.claude/settings.json` stops Claude Code reading `.env.*` files, so it couldn't confirm the file lists `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_BRAND_COMPANY_NAME` and `VITE_SHOW_DESIGN_PAGE`. On the by-hand list below.
- **Staging isn't connected to its database yet.** Until the Cloudflare variables below are set, staging keeps the language in the browser only, and /design isn't shown there.
- **Manual accessibility checks not done yet:** a screen reader pass (VoiceOver or NVDA) and 200% zoom on `/` and `/design`. For the staging check.
- **Romanian copy needs a native speaker's read** before release, especially the S1-E1-04 save messages.
- **Supabase Preview** shows as skipped on every pull request: Supabase branching isn't switched on, which is expected (migrations reach staging when `main` changes).
- **End-to-end tests run one at a time.** Fine at today's size (about a minute and a half); when the suite grows, give each test its own personas instead.

## By hand, for Robert

Four settings this epic needs that only a person with the accounts can change. Synthetic data and public values only: never paste a secret key or a service role key anywhere below.

### 1. Connect staging to its database, and show /design there (Cloudflare Pages)

1. Find the two values in Supabase: open the Supabase dashboard → project **ghemotoc-staging** → **Project Settings** (the cog at the bottom left).
   - **Project URL:** **Data API** (or **API**) → copy **Project URL** (it looks like `https://<letters>.supabase.co`).
   - **Public key:** **API Keys** → copy the **Publishable key** (starts `sb_publishable_`). If you only see the older keys, copy the one labelled **anon public**. Never the secret key or **service_role**.
2. Open the Cloudflare dashboard → **Workers & Pages** → project **ghemotoc** → **Settings** → **Variables and Secrets** (older screens call it **Environment variables**).
3. For the **Production** environment (Cloudflare's name for the `main` build, which is our staging), click **Add** three times and enter, as plain text (not "Secret"):
   - `VITE_SUPABASE_URL` = the Project URL;
   - `VITE_SUPABASE_ANON_KEY` = the public key;
   - `VITE_SHOW_DESIGN_PAGE` = `true`.
4. Do the same for the **Preview** environment, so pull request previews behave like staging.
5. Click **Save**. The values are read when the site builds, so open **Deployments**, find the newest `main` deployment, open its **⋯** menu and choose **Retry deployment**.
6. Check: open the staging site, then `/design`. The components page shows.

### 2. Load the seed personas on staging (Supabase)

Follow `docs/runbooks/staging-reset-and-seed.md`: SQL Editor → New query → paste all of `supabase/seed.sql` from `main` → Run → **Authentication** → **Users** lists 16 `@personas.test` accounts.

### 3. Staging sign-in addresses (Supabase), ready for S1-E2-01 and S1-E2-05

1. Supabase dashboard → project **ghemotoc-staging** → **Authentication** → **URL Configuration**.
2. **Site URL:** `https://ghemotoc.themagiccoffin.com` → **Save**. If that address doesn't open the site yet: Cloudflare → **Workers & Pages** → **ghemotoc** → **Custom domains** → **Set up a custom domain** → `ghemotoc.themagiccoffin.com` → follow the steps (the DNS record is added for you, because the domain is on Cloudflare).
3. **Redirect URLs** → **Add URL**, once for each:
   - `https://ghemotoc.themagiccoffin.com/**`
   - `https://*.ghemotoc.pages.dev/**` (pull request previews)
   - `http://localhost:5173/**` (your computer)
4. **Save**.

### 4. Check `.env.example` (GitHub)

1. On GitHub, open the repository → `.env.example` → the pencil icon (**Edit**).
2. Make sure these lines are there, with nothing after the `=`; add any that are missing:
   ```
   VITE_SUPABASE_URL=
   VITE_SUPABASE_ANON_KEY=
   VITE_BRAND_COMPANY_NAME=
   VITE_SHOW_DESIGN_PAGE=
   ```
3. **Commit changes…** → choose **Create a new branch** → **Propose changes** → open the pull request and merge it when CI is green (never commit straight to `main`).
