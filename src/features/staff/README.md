# Staff

The admin site: everything under `/staff`. Started by S1-E2-07a (`/staff/roles`), given its frame by S1-E11-01. Plain components, no doodles (CLAUDE.md, Designs). Loaded only when someone opens it, so staff code never ships in the reader's bundle (architecture 1.8.1).

- `components/StaffLayout.tsx`: the frame (skip link, `StaffBar` with the areas the person may open, the page, `StaffFooter`); a member or a visitor gets `StaffAccessRefused` instead. `StaffHomePage.tsx` is `/staff`.
- `staffAreas.ts`: which area (from `staff_role_areas`) opens which page. Each staff story adds its line.
- `hooks/useMyStaffAccess.ts` and `api/staffAccess.ts`: `my_staff_areas()`, the person's own roles and username.
- `components/AuditLogPage.tsx` (`/staff/audit-log`, S1-E11-01): `AuditLogFilters`, `AuditLogTable`; `hooks/useAuditLog.ts`, `api/auditLog.ts` (`admin_search_audit_log()`, `admin_export_audit_log()`), `lib/auditLogCsv.ts` (the CSV file).
- `components/users/` (S1-E11-02): `UsersPage` (`/staff/users`, search by username, pen name, email or user ID, with `UserResults`), `AccountPage` (`/staff/users/:userId`: `AccountSummaryRows` with `ShortUserId`, `AccountActions` with `AccountActionForm`, the moderation feature's `AccountSanctions`, `AccountOpenCases` and `AccountAuditRows`), `UsersTabs` (Accounts, Invites and, for those who act, Manual age checks); `hooks/useUserLookup.ts`, `useAccount.ts`, `useAccountActions.ts`, `useAccountWords.ts`, `api/userManagement.ts` (`admin_user_lookup()`, `admin_user_account()`, `admin_account_open_cases()`, `admin_reset_pen_name()`, `admin_sign_out_everywhere()`, plus `admin_apply_sanction()`, `admin_approve_username()` and, for an active 13-to-15, `admin_withdraw_parental_consent()` (S1-E2-03)).
- `components/age-checks/ManualAgeChecksPage.tsx` (`/staff/users/age-checks`, the Users area's tab for owner, admin and moderator; S1-E2-08b): `ManualAgeCheckCard` (the year of birth, the result now, when asked, the answer-by date and the Yoti attempts) with `ManualDecisionForm`; `hooks/useManualAgeChecks.ts`, `api/manualAgeChecks.ts` (`admin_manual_age_checks()`, `admin_decide_manual_age_check()`).
- `components/invites/InvitesPage.tsx` (`/staff/users/invites`, the Users area's second tab since S1-E11-02; `/staff/invites` redirects; S1-E11-17): `MakeInviteForm`, `NewInviteLink` (the code, shown once), `InviteRow` with `InviteStatusPill`; `hooks/useInviteLinks.ts`, `api/inviteLinks.ts` (`admin_create_invite()`, `admin_list_invites()`, `admin_revoke_invite()`).
- `components/StaffRolesPage.tsx` (`/staff/roles`, S1-E2-07a): `GrantRoleForm`, then a `StaffMemberCard` per staff member with `PermissionChecks`; `hooks/useStaffRoles.ts`, `api/staffRoles.ts`. A role change needs a sign-in from the last 15 minutes (S1-E11-01).
- `components/AccountPicker.tsx`, `AccountResults.tsx`, `AccountOption.tsx` (S1-E11-01b): "Find the account" inside `GrantRoleForm`; `hooks/useAccountSearch.ts`, `api/accountSearch.ts`. A grant uses the picked account's user ID; each refusal names its problem (`failureFromRefusal()` in `api/staffRoles.ts`).
- `components/metrics/MarchNumbersPage.tsx` (`/staff/metrics`, S1-E15-02): the March test numbers, `MarchTargetCard` × 3 and `MarchNumberLists` (writers by market, reads per day); `hooks/useMarchNumbers.ts`, `api/marchNumbers.ts` (`admin_march_numbers()`), `lib/marchNumbers.ts` (progress and market names). Owner and admin; a moderator sees a pointer to the queue.
- `components/metrics/` from S1-E11-04, on the same page: `MetricsOverviewSections` (`AgeNumbersCards`, `TierNumbersTable`; `hooks/useMetricsOverview.ts`, `api/metricsOverview.ts`, `lib/tierShares.ts`), `AnalyticsCards`, `ComplianceLogSection` (`ComplianceEntryForm`, `CompleteEntryForm`, `ComplianceLogTable`, `LaunchTaskCard`; `hooks/useComplianceLog.ts`, `api/complianceLog.ts`, `lib/complianceEntryForm.ts`, `lib/complianceLogCsv.ts`) and the shared `MetricsCard`. Owner and admin only.
- `components/classics/ClassicsPage.tsx` (`/staff/classics`, S1-E11-16 part 16a): add a public-domain work (`ClassicWorkForm` with `ClassicAuthorFields`, `ClassicStoryFields`, `ClassicSourceFields` and `FreeMarketsList`), its text (`ClassicTextForm`, split by `lib/splitClassicText.ts`), publish and unpublish (`ClassicCard`); `hooks/useClassics.ts`, `api/classics.ts`, `lib/publicDomain.ts`. Owner and admin.
- Part 16b on the same page: `ClassicsImport` (a research list as drafts, `lib/parseClassicsCsv.ts`), `ClassicSuggestionsPanel` (who became free on 1 January) and `ClassicTypoFix` (a typo fix kept as a version); `hooks/useClassicsImport.ts`, `hooks/useClassicTypoFix.ts`, `api/classicsImport.ts`.
- `components/schools/TeacherChecksPage.tsx` (`/staff/schools/teachers`, S1-E2-11): Verify teachers, a `TeacherCheckCard` per waiting request ("Open the proof" logs a sensitive read; `TeacherDecisionPanel` approves or says "Not yet" with a reason, deleting the proof first) and `TeachersList` (remove a badge with a reason); `hooks/useTeacherChecks.ts`, `api/teacherChecks.ts` (`admin_teacher_checks()`, `admin_teachers()`, `admin_open_teacher_proof()`, `admin_decide_teacher_check()`, `admin_remove_teacher_badge()`). Owner, admin and moderators with the teacher checks permission.
- `components/schools/ClassSpacesPage.tsx` (`/staff/schools/classes`, bundle CLASSES, part d; S1-E8-11 criterion 10): the manual pilot mode. `NewClassSpaceForm` sets up a class owned by a named teacher with its school (`admin_create_class_space()`); each `StaffClassCard` shows the school, teacher, members and status, with `StaffClassSchoolForm` (`admin_set_class_school()`) and `StaffClassActions` (the code to print through `make_class_invite()`, archiving through `archive_class_space()`). `SchoolsTabs` links it with Verify teachers. `hooks/useStaffClassSpaces.ts`, `api/staffClassSpaces.ts`. Same access as Verify teachers.
- `registerStaffTranslations.ts`: the `staff` text namespace, added when the shell loads.
- The database side: `supabase/README.md`, "Staff roles" and "The admin shell". The server checks every rule and writes the audit log; the pages only show the choices the person has.
